# T03 kernel decisions and task boundary

Author candidate, 2026-09-11; independent semantic review remains required. Contracts: `sched.m1/revision-1`, `program-transport.m1/revision-1`, and the root-reviewed corrections in `t03-contract-corrections.md`.

The pure Rust kernel owns immutable validated programs, thread/core lifecycle, the global ready FIFO, checked event ordering, interpreter execution, and fatal cleanup. `Policy` supplies a FIFO-head choice and an optional positive useful-service quantum matching the persisted policy configuration. T03 supplies no production implementation of that trait. Its `TestPolicy` is compiled only by tests; applying reference cases through that driver verifies kernel mechanisms, not completed T04/T05 policy integration. `build_probe` remains unchanged for adapters.

`advance_tick` closes phases 1–3 and the ascending-core phase-4 scan fixpoint before returning. Initial `Created` state has all threads not arrived. State queries never expose an intermediate phase. Returned `Boundary` owns the actual canonical events and closed half-open intervals; the kernel does not retain prior batches. `State` is explicitly a kernel inspection value, not the T02 protocol Snapshot: command routing, inspection sequences, deltas, pause/cancel chunks, worker bridging, and terminal transport replies remain T07. Metrics and bounded retention remain T06; replay/checkpoints remain T13. A single tick is bounded by the configured run-wide control budget, but no responsiveness or benchmark claim is made for extremely large budgets.

## Interpreter and time

The decoder compiles structured repeats into immutable instructions and backedges with original source IDs. Each thread owns a program counter, bounded loop stack, remaining compute service, and instruction occurrence token. A repeat consumes one control unit immediately before each iteration body; final fall-through consumes none. An empty repeat of count N costs N units, as required by C09. Each yield, I/O submission and end also consumes one unit. The run-wide counter resets only when the next applicable event advances simulated tick, never on a thread switch or phase-4 rescan. An I/O-blocked state retains the I/O source; completion advances the pointer before readiness. Yield advances the pointer before readiness. Fatal and terminated sources remain inspectable.

Only the earliest applicable compute/quantum deadline is inserted. With remaining service R and remaining grant Q, check `tick + min(R,Q)`; without a grant check `tick + R`. Insert compute completion when R <= Q, expiration when Q <= R, and both on equality in that order. Earlier completion preserves unused quantum for the next compute instruction. Equality followed by another compute inserts a phase-3 token for the new instruction occurrence with zero remaining grant; it does not insert a same-tick phase-1 completion. This root/auditor-approved choice prevents errors caused solely by an irrelevant later deadline. It preserves all finite scheduling traces while reporting overflow when the next required boundary is unrepresentable.

The event heap key is `(tick, phase, insertion_sequence)`; other fields only distinguish structurally impossible equal-sequence keys. Scheduling scans produce events in ascending core order. Later equal-phase events retain insertion order, even when that order differs from core order after separate scans. Tokens check ownership, core dispatch generation, and instruction occurrence. Stale entries do not advance time or produce events/intervals.

## Counters, identities and error boundary

Each core starts with generation zero and increments once, checked, when reserved; first dispatch is generation one. Releases invalidate ownership without incrementing an already exhausted generation. Compute occurrences have a separate checked counter, preventing an old token for the same repeated source block from applying to a later occurrence. Pending insertion capacity is checked for the whole operation before its event or lifecycle mutation. Tick, generation, insertion, and occurrence overflow is attributable to the current thread/block.

Ordinary canonical events use sequences 1 through `u64::MAX - 1`; the last representable slot is reserved for a fatal event. An attempted ordinary event after that range fails before its associated mutation. Thread-attributable failures report `arithmeticOverflow`; an unassignable engine counter failure reports global `internalEngine`. The dedicated terminal emission can consume sequence MAX, after which no operation executes. Final cleanup discards the entire pending heap and ready queue, releases cores, closes nonzero intervals at the error tick, preserves prior terminations, and marks the culprit error and all other unfinished threads censored. Ownership removal plus terminal status invalidates tokens without further potentially overflowing generation increments.

Event IDs are `${machine}:event:${sequence}`. Core entity IDs begin `${machine}:core:${index}` and append `:` until distinct from every declared thread ID, following the root-approved bounded generated-ID contract. Core events order entities `[threadId, coreEntityId]`; other thread events contain the thread alone; global events contain none. A thread event points to the immediately preceding event for that thread, if any. A global event points to the immediately preceding canonical event, if any. These links are deterministic predecessor provenance, not a complete causal graph.

## Decoding

Direct Rust dependencies are pinned to serde 1.0.228 and serde_json 1.0.149; transitive versions/checksums are committed in Cargo.lock. The decoder checks the raw 1 MiB input limit before parsing, bounds JSON structural nesting at 160 before disabling serde's default 128-level limit, then applies the program depth limit of 64. This accommodates the object/array levels of valid repeat ASTs while bounding hostile parser recursion. Program/workload shape is closed, integers are parsed from canonical decimal strings directly to u64/i64, and semantic identity, parameter, flow, and size limits are checked atomically. Eight existing T02 fixtures target this decoder subset; command/reply fixtures are not claimed as Rust routing/transport coverage. Additional tests exercise exact depth, count, byte, Unicode scalar, lexical, range and compatibility boundaries.

The test `generated_ids_causal_predecessors_and_producer_artifact` writes actual four-case canonical output only when `OS_LAB_KERNEL_EVENTS` is supplied: `{ "cases": [{ "name", "workload", "events" }] }`. Root's independent Node validator consumes that artifact against the shared event schema and source mappings. No fixture snapshot substitutes for kernel execution.
